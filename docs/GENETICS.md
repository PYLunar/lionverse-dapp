# 遗传协议 v2

`shared/genetics.json` 是概率、等位基因名称与索引顺序的权威配置。`npm run generate:traits` 生成 Solidity 配置；提交配置时必须同时提交生成文件。基因排序属于数据协议，不可为调整界面顺序而修改。

## 数据结构

每只狮子保存 `uint8[18]`，每两个值组成一个基因座，顺序如下：

| 基因座   | 两份基因的位置 | 取值                   |
| -------- | -------------- | ---------------------- |
| 基础品种 | 0、1           | 原野、雪域、黄金、钻石 |
| 毛色     | 2、3           | 6 种毛色               |
| 鬃毛     | 4、5           | 9 种鬃毛               |
| 瞳色     | 6、7           | 7 种瞳色               |
| 花纹     | 8、9           | 6 种花纹               |
| 性格     | 10、11         | 6 种性格               |
| 光效     | 12、13         | 4 种光效               |
| 冠饰     | 14、15         | 4 种冠饰               |
| 光谱倾向 | 16、17         | 自然、炫彩、黑白炫彩   |

前八项按索引较小者显现。不同等位基因的另一份仍可遗传，例如 `[原野, 钻石]` 显示原野，但能传递钻石。两位这样的携带者，在不计变异与光谱判定时，各贡献钻石的概率为 `1/2 × 1/2 = 25%`。

光谱倾向是特殊的概率性状，不适用“两份相同必定显现”。即使两份都是炫彩倾向，也必须通过后述稀有判定。未显现的光谱倾向仍可遗传，其持有者不因此提高外观稀有度。隐性表示不显现在外观，所有基因仍在公链公开。

## 初代

普通基因座先按权重产生显现值，再抽另一份基因。第二份若比显现值更显性，则钳制为显现值，从而保留原来的初代外观分布，同时引入隐性携带。

光谱判定使用独立哈希域。最终初代品种概率为：

|     原野 |     雪域 |    黄金 |    钻石 | 普通炫彩 | 黑白炫彩 |
| -------: | -------: | ------: | ------: | -------: | -------: |
| 31.4721% | 12.1827% | 4.5685% | 1.7766% |      25% |      25% |

初代随机铸造的炫彩总概率为 50%：普通炫彩 25%，黑白炫彩 25%。非炫彩初代也可能携带光谱倾向：其第二份光谱基因按自然 97%、普通炫彩 2.99%、黑白炫彩 0.01% 抽取。显现炫彩的初代将两份光谱基因设为对应倾向。基础品种与最终炫彩外观分开保存，保证炫彩双亲能产生正常的基础品种。

## 子代与变异

每个基因座从两位亲代各随机取一份基因，各等位基因的传递机会为 50%。然后以 `1/8` 概率选择其中一份进行加权重抽；一次变异不会重抽两份。重抽可能得到原值，因此实际可见变化概率不等于 12.5%。

这一规则也适用于光谱倾向的传承，但最终是否显现炫彩，独立按**亲代状态**决定，不取决于子代是否凑齐两个炫彩等位基因。

| 亲代状态（自上而下优先匹配）     | 子代炫彩总概率 | 非炫彩概率 |
| -------------------------------- | -------------: | ---------: |
| 两位均已显现炫彩，包含黑白炫彩   |             6% |        94% |
| 一位已显现炫彩                   |             3% |        97% |
| 无显现炫彩，但两位都携带光谱倾向 |             1% |        99% |
| 无显现炫彩，一位携带光谱倾向     |           0.5% |      99.5% |
| 两位都没有光谱倾向               |           0.1% |      99.9% |

已经命中炫彩的结果，进一步判定是否为黑白炫彩：

| 亲代状态（自上而下优先匹配）         | 黑白占本次炫彩结果的比例 |
| ------------------------------------ | -----------------------: |
| 两位均为黑白炫彩                     |                       1% |
| 一位为黑白炫彩                       |                     0.5% |
| 均未显现黑白，但至少一位携带黑白倾向 |                     0.2% |
| 其余组合                             |                     0.1% |

因此，没有黑白倾向的普通炫彩双亲：普通炫彩 **5.994%**，黑白炫彩 **0.006%**，非炫彩 **94%**。黑白双亲：普通炫彩 **5.94%**，黑白炫彩 **0.06%**，非炫彩 **94%**。

自然觉醒可以发生在两位亲代都没有光谱倾向时；成功后将子代第一份光谱基因至少提升到对应倾向，使新外观有可继承的基因记录。极低概率不是唯一性保证，也没有保底或固定黑白总量配额。

## 概率预览与一致性

普通性状预览枚举四种双亲传递组合，再精确展开变异分支；基础品种结果还乘以非炫彩概率。炫彩与黑白概率分别展示，不混淆条件概率与最终概率。

JS 与 Solidity 都使用 `keccak256(abi.encode(seed, domain, locus))`：域 0/1 用于初代，2/3 用于双亲传递，4/5/6 用于变异，20/21 用于光谱判定。对照测试检查相同种子的完整 18 个基因值及显现结果。

种子仍是教学用链上伪随机数，调用者或区块生产者可能筛选结果。上述概率是均匀种子假设下的理论规则，无法替代 VRF。若赋予藏品真实经济价值，需先升级随机源并审计。

## 版本与迁移

- 协议版本由 `GENETICS_VERSION()` 返回，前端拒绝连接旧版本合约。
- 原 ERC-721 合约不可升级。v2 是新合约，旧合约及其资产不会被修改或搬移。
- 旧演示键 `lionverse-demo-v2` 保留。迁移写入 `lionverse-demo-v3`，保存编号、主人、时间、外观、双亲及冷却状态。
- 历史数据没有双基因记录，迁移将原特征视为同型，标记 `geneticsOrigin=legacy-homozygous`，不会捏造隐性历史。旧炫彩的基础品种默认原野，光谱倾向设为炫彩；外观保持原样。
- 后续修改索引、显性顺序或随机哈希域，都属于协议变更，需要明确版本、对照用例及迁移方案。
